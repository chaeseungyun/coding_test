# 일일 코테 문제 만들기

이 저장소에서 하루에 문제 하나. 사용자는 플랫폼을 열지 않는다. 에이전트가 `STUDY_PLAN.md`를 보고 오늘 파일을 만든다.

유저 대면 메시지는 **한국어**. 풀이·알고리즘 힌트는 파일을 만들 때 **절대 적지 않는다.**

## 언제

- "오늘 문제", "문제 만들어줘", "D12 문제", "내일 거"
- 날짜만 말하고 문제를 달라는 경우

이미 오늘 파일이 있으면 덮어쓰지 말고 경로만 알려 준다. 다시 만들라는 요청이 있을 때만 덮는다.

## 워크플로

1. `STUDY_PLAN.md`를 읽는다. **시작일**과 주차별 문제 표를 기준으로 한다.
2. 대상 날짜를 정한다.
   - 기본: 대화의 오늘 날짜 (`user_info`)
   - "내일" / "D37" / 특정 날짜가 있으면 그걸 쓴다
3. 일차 `Dn`을 계산한다. `n = (대상날짜 - 시작일).days + 1` (D01이 시작일).
4. 표에서 그날 문제·유형·플랫폼·폴더를 고른다.
5. `유형폴더/YYYY-MM-DD-문제이름.py` 가 없으면 만든다. 폴더도 없으면 만든다.
6. 사용자에게 경로, 한 줄 요약, 실행 커맨드만 안내한다. 접근법·정답은 말하지 않는다.

### 복습 날

- 표에 "또는 …" 대안이 있으면 **그 문제를 낸다.**
- 순수 복습·약점 복습이면, 그 주 유형으로 **같은 난이도의 새 문제**를 만든다. 예전 파일을 복사하지 않는다.
- D63 회고일은 문제를 만들지 말고, `STUDY_PLAN.md`의 회고 항목을 채우라고 안내한다.

### 폴더

| 주 | 폴더 |
|----|------|
| 1 | `01-implementation/` |
| 2 | `02-hash/` |
| 3 | `03-stack-queue/` |
| 4 | `04-sort-greedy/` |

| 그 외 복습 창작 | `10-review/` |

파일명 문제이름은 한글·하이픈. 공백 없음. 예: `2026-08-20-문자열-내-p와-y의-개수.py`

## 파일 규칙

언어는 **Python 3**. 파일은 `.py` 하나. 문제 지문은 주석으로 파일 안에 전부 넣는다. 링크만 주고 끝내지 않는다.

- 시그니처는 문제에 맞게. 프로그래머스 스타일이면 `def solution(...):`
- 본문은 `...` 만. `pass`로 숨은 정답을 넣지 않는다
- 주석에 접근·힌트·의사코드·정답 복잡도 해설을 쓰지 않는다. `접근:` 세 줄은 빈칸으로 둔다
- 백준 문제여도 이 저장소에서는 `solution(...)` + 테스트 리스트로 돌리게 바꾼다. `input()` 숙제는 내지 않는다
- 공식 예제 + 엣지 케이스를 `tests`에 넣는다 (빈 값, 둘 다 0, 최댓값 근처 등)
- 테스트 루프는 아래 템플릿을 유지한다

골드 예시: `01-implementation/2026-08-20-문자열-내-p와-y의-개수.py`

### 템플릿

```python
# D{n} | {주차} {유형}
# 접근:
# 시간복잡도:
# 막힌 지점: (없으면 "없음")
#
# ------------------------------------------------------------
# 문제: {문제 이름}
#
# {지문. 조건·규칙을 빠짐없이. 한국어.}
#
# 제한
# - ...
#
# 입출력 예
#   {입력}  -> {출력}    ({한 줄 이유})
# ------------------------------------------------------------

def solution(...):
    ...


if __name__ == "__main__":
    tests = [
        (입력튜플또는값, 기대값),
    ]

    for args, expected in tests:
        got = solution(*args) if isinstance(args, tuple) else solution(args)
        ok = "OK" if got == expected else "FAIL"
        print(f"[{ok}] solution({args!r}) = {got!r} (expected {expected!r})")
```

단일 인자면 D01처럼 `solution(s)` 로 단순하게 호출해도 된다.

## 지문 쓰는 법

표의 문제 이름을 그대로 쓰되, **사이트에 가서 복붙하지 않아도 풀 수 있게** 조건을 재작성한다.

- 입력, 출력, 제한, 예제 2개 이상
- 예제마다 왜 그 답이 나오는지 짧게
- 난이도는 그날 표 수준. 1기 습관 형성이므로 몰아넣지 않는다
- 별표(`*`) 문제여도 일단 그 문제를 낸다. 사용자가 어렵다고 하면 같은 유형의 쉬운 대체 문제로 다시 만든다

## 하지 말 것

- 정답 구현, 힌트가 되는 함수명/`TODO`
- 마크다운 문제 파일, 노트북, 여러 파일로 쪼개기
- 하루에 2문제
- 플랜에 없는 고급 유형(세그트리, 플로우 등)을 임의로 넣기
- 테스트 없이 빈 `solution`만 주기
- 파일을 만든 뒤 `python`으로 돌려 보며 정답을 검증하려고 채우기

## 안내 메시지 (만든 직후)

짧게. 예:

- 오늘(날짜)은 **Dxx — 문제이름**
- 경로
- `solution`만 채우면 된다 (한 줄 조건)
- 실행: `python {경로}`
- 막히면 15분 뒤 힌트만 달라고 하면 된다

정답·접근 후기는 사용자가 풀이를 요청하기 전에는 하지 않는다.
